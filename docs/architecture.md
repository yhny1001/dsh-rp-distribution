# Plugin architecture

English | [中文](architecture.zh.md)

`dsh-rp-distribution` is open RP infrastructure, a plugin framework, and a shared contract layer built on DeepSeek Harness. This repository contains its Cordis plugin release family; it has no DSH application entry and no private copy of Host services. ST compatibility and `@dsh-rp/product` are first-party adapters and references rather than the infrastructure's only data source or UI.

## Package layers

The RP service packages own versioned contracts and reversible registrations. `distribution-core` declares the presentation-neutral mount order. `distribution-web` declares only `ui-slot-runtime` and `web`; `distribution` concatenates those two patch layers as the one-command Web entry. Tests keep the aggregate Patch byte-identical to its owners.

`@dsh-rp/product` is a local-first product Bundle independent from the complete distribution family. It packs a Node API, Client UI, clean-room SillyTavern import path, and distinct `rp-tavern`/`rp-agent` Agent presets into one installable Tarball and uses only the `webServer`, `commands`, `agentPresets`, Session events, and official Web Slots already present in DSH `0.1.0-rc.6`. It starts no second generation loop. Two hundred fifty-six stable System Prompt seats start at order 1000 and project a mutable Prompt Manager order while as many as 1,024 retained definitions preserve unassigned alternatives. Host foundation sections and the ST Role Protocol precede imported seats; an order ending in Assistant Prefill reserves that layer for the final seat and places product Runtime Mode immediately before it, so DSH tool requirements do not supersede ST's terminal generation start. A Prefill with an open planning, thinking, or reasoning tag remains as escaped source text with private-reasoning intent; when a model still leaks it into an ordinary Text Block, pure presentation projection deterministically removes named private-planning blocks while retaining the complete Session source. Every non-History layer enters `request/header.header.system` through `@deepseek-ai/dsh-system-prompt`; the Client exposes the route to the Provider's `request.system` and distinguishes the Host's same-named dynamic Context Snapshot so a permission snapshot cannot be mistaken for the complete System Prompt. Markers resolve system rules, world facts, the character cast, user persona, scene, examples, and the Host-owned chat-history position; a pure text assembler resolves identity and ordered `setvar/getvar` macros without executing scripts. `agent/inbox/claimed` supplies current user prose before its first-step Session Surface append so `lastUserMessage` expands on the first model request; later steps read the latest native user message. An imported source document remains attached to a selectable `sillytavern` preset. An explicit, non-destructive adaptation creates or refreshes a separate `harness` preset, normalizing injection metadata to sequential seats while retaining source identity, content, enablement, and generation settings. Supported generation scalars flow through the `agent/request` waterfall and are logged in request headers. Hash-addressed PNG card bytes live beside product state and are served through a same-origin immutable asset route. A product transcript projection records the persona or primary character selected when each append-origin message lands. Body edits preserve the original transcript and add provenance-complete Surface replacements; idle assistant-history edits use an explicitly framed `plugin/recall` user-role node because core assistant events are Step-scoped.

The product ships `rp-tavern` and `rp-agent` as separate Agent presets over the same imported resources. Tavern Chat registers prompt assembly only; Agent RP additionally registers model tools for domain Effects and structured choices. Tool calls/results are the durable Session evidence, while the product file stores a revisioned projection rendered into the next request and the RP conversation view. World Info remains entry-addressable with keys, enablement, constant status, and priority. Current Agent Effects cover world, time, scene, character, persona, relationship, and memory; choice selection feeds the exact stored prompt back to the same Session. A future State Keeper Sidecar must audit prose-implied changes at the Turn boundary because prompt instructions alone cannot guarantee every model emits the required tool call.

Every `@deepseek-ai/*` package is an external Peer. Exact development versions are read from package Manifests by `scripts/fetch-host-sdk.ts`; their npm artifacts form an ignored SDK cache. The cache can be deleted at any time and is never part of an npm payload.

## Compatibility ownership

Core code compiles against published Host service packages. The Web plugin additionally needs generic slots for RP Studio and conversation placement, plus the alternative conversation-submission API. Until those declarations ship in the selected public Host packages, `types/host-extensions.d.ts` records the exact type-only requirement. It contains no implementation or fallback.

Runtime compatibility therefore remains fail-closed: an older Host cannot acquire missing services by installing this plugin, and installation never modifies Host code. A DSH release supports the Web bundle only when it implements the extensions listed in [compatibility.md](compatibility.md).

## Testing split

RP unit tests own package behavior, lifecycle rollback, policy, persistence adapters, package compatibility, API validation, and browser presentation. Small browser Host contracts used by component tests live under `tests/host` and are not published. The product Bundle is additionally verified with a disposable DSH home, its actual Tarball, a real Web Profile, and the Codex in-app Browser; the complete distribution family's Host assembly remains a separate acceptance surface.
