# @dsh-rp/projection

[English](README.md) | 中文

`projectRpScope()` 与 `ctx.rpProjection.projectScope()` 会在指定 Session 事件边界，为一个精确作用域物化按所有者区分的状态、记忆、关系、场景、分支与对话历史。Turn 准备阶段直接从日志冻结该结果，因此下一轮无需把 effects 复制进多套可变 Store 就能看到上一轮提交；崩溃后恢复的 Session 也执行完全相同的折叠。

`projectRpSession()` 从完整、有序的会话日志重建当前 RP 状态与执行拓扑。`ctx.rpProjection` 为实时 `Session` 暴露相同折叠。本包不保留缓存，并会拒绝同一轮次 id 出现多个提交或中止终态事件。

轮次提交按最新提交值更新状态和场景，按 id 更新记忆，按有向实体对更新关系，按分支 id 更新分支。因此编辑、回放、恢复和 fork 行为都依赖同一个持久真源。

能力授权和最终结算事件会按 Tool Call id 重建 Agent 决策时间线，其中包含有效信任、权限、预算、网络域名、文件根、Policy 层和失败诊断。

组件组合、上下文、Pipeline 阶段、委派 Agent、状态校验、分支激活、记忆接受与压缩，以及外部媒体工作都会重建为带类型的生命周期投影。每个阶段都携带其 Pipeline id、种类和快照 hash，因此嵌套或并发图仍然没有歧义。该折叠是严格状态机：没有开始的完成、重复终态或冻结身份变化都会失败，不会虚构缺失历史。若不存在独立生命周期事件，原子 Turn Commit 可以提供自身完整的组合、Pipeline、状态、记忆、分支和 Agent 轨迹。

## 模型体验

通过渲染选定投影字段的提示词或上下文插件间接产生影响。

#### KV Cache 影响

无直接影响。投影消费者决定哪些追加事实进入后续请求。

## 已知限制与延期工作

- **全日志折叠**——检查点和增量投影提供方可以替换本实现而不改变结果类型。
